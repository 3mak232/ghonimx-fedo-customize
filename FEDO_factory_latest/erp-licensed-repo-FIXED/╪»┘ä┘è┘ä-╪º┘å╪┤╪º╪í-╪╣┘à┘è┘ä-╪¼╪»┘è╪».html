المرحلة 1 — إنشاء مشروع Supabase جديد للعميل

ادخل supabase.com/dashboard

اضغط New project > اختر Organization > اسم المشروع مثال erp-client-acme > اختر Region قريب من مصر (مثال Frankfurt) > ضع Password قوي > Create new project وانتظر دقيقة حتى يجهز.

انسخ بيانات المشروع

من القائمة اليسار Project Settings > General انسخ Reference ID. ثم API Keys انسخ URL (مثال https://xxxx.supabase.co) و publishable key (sb_publishable_...) و اضغط Reveal وانسخ Secret key (sb_secret_... = هذا هو ADMIN_SECRET_KEY).

ستحتاج الـ URL والـ publishable للواجهة، والـ Secret للدوال.

الاسم: admin-create-user — اترك Verify JWT مفعل — الصق erp-kit\02-edge-functions\admin-create-user\index.ts

دالة full-backup — بـ JWT

دالة full-restore — بـ JWT

الاسم: full-restore — الصق erp-kit\02-edge-functions\full-restore\index.ts

المرحلة 4 — وضع الـ Secrets (3 أماكن مختلفة — لا تخلط)

ADMIN_SECRET_KEY ليس اسم من Supabase، هو اسم متغير اختاره المطور. تجده في Supabase باسم Secret key (sb_secret_...) وليس sb_publishable_....

للوحة wqfbabtbqyioqumqjerc (مرة واحدة): دالة push-license تحتاج 2

Edge Functions > push-license > Secrets أو Vault > Add secret:
1) LICENSE_PRIVATE_KEY = الطويل من المرحلة 0
2) ADMIN_SECRET_KEY = الـ sb_secret_... الخاص بمشروع اللوحة نفسه (Project Settings > API Keys > Secret key > Reveal)

للعميل الجديد: دالة license-sync تحتاج 3

Edge Functions > license-sync > Secrets:
1) LICENSE_PUBLIC_KEY = القصير من المرحلة 0 (نفسه لكل العملاء)
2) CLIENT_ID = ستجلبه من اللوحة في الخطوة التالية (اتركه فاضي الآن وارجع له)
3) ADMIN_SECRET_KEY = الـ sb_secret_... الخاص بمشروع العميل نفسه (مش اللوحة!)
لو وضعت publishable مكان Secret ستظهر 500 Secrets ناقصة أو 401 invalid signature

فين أجد sb_secret_...؟

Project Settings > API Keys > قسم Secret keys > زر Reveal. سابقاً كان اسمه service_role.

المرحلة 5 — تجهيز الواجهة ورفعها

عدّل رابط المشروع في ملفين

افتح المجلد erp-kit\03-frontend من النسخة المُصلحة:
1) app.js السطر 1: بدّل __SUPABASE_URL__ برابط العميل (https://xxxx.supabase.co) و __SUPABASE_ANON_KEY__ بالـ sb_publishable_... للعميل
2) index.html: بدّل __SUPABASE_URL__ في سطر preconnect بنفس رابط العميل (اترك https://cdn.jsdelivr.net و fonts.gstatic.com كما هي)

ارفع الواجهة

ارفع محتوى مجلد 03-frontend فقط على Cloudflare Pages (Create project > Upload folder) أو Netlify Drop. لا ترفع ملفات SQL ولا docs.

أضف رابط الموقع في Supabase

في مشروع العميل: Authentication > URL Configuration > Site URL ضع رابط موقعك (https://xxx.pages.dev) > Save

المرحلة 6 — أول مستخدم وربط الترخيص (أهم خطوة)

سجّل أول مستخدم

افتح رابط موقع العميل > سجل يوزر جديد (إيميل وباسورد). أول يوزر يصبح admin تلقائياً. بعدها في Supabase: Authentication > Providers > Email > Disable sign-ups (اقفل التسجيل).

أنشئ سجل العميل في اللوحة

افتح لوحة wqfbabtbqyioqumqjerc (04-dashboard) > تبويب العملاء > + عميل > املأ الاسم والموبايل > في حقل رابط license-sync ضع https://<ref-العميل>.supabase.co/functions/v1/license-sync > حفظ. افتح العميل مرة أخرى وانسخ الـ CLIENT_ID (UUID).

ارجع ضع CLIENT_ID عند العميل

في مشروع العميل: Edge Functions > license-sync > Secrets > أضف CLIENT_ID = الـ UUID اللي نسخته. ثم اعمل Deploy مرة أخرى للدالة لتأخذ السر الجديد.

فعّل الاشتراك وأرسل الترخيص (بدونها العميل بلا حدود!)

في اللوحة: تبويب العملاء > زر الاشتراك > اختر الخطة والتاريخ > حفظ > ثم إرسال الترخيص > ثم فحص. يجب أن ترى تمام و مطابق في تبويب المتابعة. لو ظهر invalid signature راجع المفاتيح، ولو Secrets ناقصة راجع المرحلة 4.

المرحلة 7 — اختبار نهائي قبل التسليم

سجل دخول وجرّب

ادخل بمستخدم عادي > افتح كل صفحات القائمة > تأكد لا يوجد Error أو NaN.

اختبر الحدود

قلّل الخطة لمستخدم واحد وحاول إضافة يوزر ثاني من admin-create-user > يجب أن يرفض وصلت للحد الأقصى للمستخدمين. عطّل وحدة من الخطة وحاول إضافة سجل لها > يجب أن يرفض وحدة ... غير مفعّلة.

اختبر الإيقاف

من اللوحة غيّر الحالة إلى موقوف > إرسال > يجب أن يقفل موقع العميل ويخرج المستخدمين (حساب developer فقط يمر).

افحص RLS

في مشروع العميل: SQL Editor > شغّل 07-local-test\ERP_rls_audit_READ_ONLY.sql > الخمس فحوص يجب أن تكون 0.

جرّب النسخ الاحتياطي

انسخ 04-backup لريبو خاص جديد > ضع الـ Secrets الثمانية > شغّل الـ workflow يدوياً > جرّب استرجاع على مشروع ثانٍ.

أخطاء شائعة وحلها

بيانات الدخول غير صحيحة رغم صحتها → Authentication > Users اضغط اليوزر > Confirm email، وتأكد Providers > Email مفعل، وتأكد المفتاح في الداشبورد يطابق نفس المشروع.

invalid input syntax for type uuid → نسخت الـ UUID ومعه نص > Users أو مسافة. انسخ الـ ID فقط بدون مسافات.

Syntax error at // → شغلت gen_keys.mjs في SQL Editor. هو يشتغل في المتصفح عبر gen_keys.html دبل كليك، أو في PowerShell بـ node gen_keys.mjs.

Secrets ناقصة → نسيت secret في Vault. راجع المرحلة 4.

stale or missing issued_at / wrong client → الـ CLIENT_ID لا يطابق، أو الساعة بين السيرفرين فرقها > 15 دقيقة (نادر).
